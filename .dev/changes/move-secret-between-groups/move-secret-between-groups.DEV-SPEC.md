# SPEC: 移动秘密到其他分组 + 点击引用按需刷新快照

> 本文件是本轮代码变更的活文档，随讨论演进；存放于 `.dev/changes/<slug>/` 活动变更工作区（仓库 `.dev` 布局）。任务关闭前将持久知识迁移回代码/文档，经用户许可后删除本目录或移至 git 忽略的归档。

## 1. Problem Statement（用户视角）

秘密库插件中，秘密按「分组」组织，每个分组有独立口令。当前存在两个问题：

1. 用户想把某个分组中的秘密移动到另一个分组（例如把 `API` 组中的「阿里百炼 | 语音API」并入 `default` 组），但插件没有「移动」能力。现有替代路径是：删除该秘密再在新分组重建 —— 这会生成新的秘密 ID，导致文档中所有引用失效，且需要重新输入明文内容。
2. 文档中的引用段落携带非敏感快照（label、分组名、时间戳）。秘密被修改或移动后，快照会陈旧（例如引用仍显示「阿里百炼 | 语音API · API」，而秘密已不在 API 组）。用户希望：点击引用、弹框弹出时检查该引用是否需要更新，如有需要则更新块属性或块内容。

**用户定义的成功标准**：
- 可以一次勾选多条秘密并移动到目标分组；移动后文档引用依然有效（点击可打开）。
- 点击旧快照的引用时，弹框展示前引用自动更新到最新 label / 分组名；不扫描文档、不影响其他引用。
- 分组口令保持各自独立，移动动作不改变任何口令。

## 2. Approach

- **数据层**：新增「批量移动」持久化 mutation。对每条秘密：用**源分组密钥**解密 → 用**目标分组密钥**重新加密 → 更新 `groupId` / `encryptedContent` / `updatedAt`。密钥由 PBKDF2 从各自分组口令派生，密文经 AES-GCM 的 AAD 绑定 `group:<groupId>:secret:<secretId>`，不换组重加密则无法解密（crypto.ts）。秘密 ID 不变 —— 这是文档引用继续有效的关键。
- **授权**：每条秘密需要源组密钥（解密）和目标组密钥（加密）。任一未解锁时由移动对话框就地输入口令；口令校验失败（含 verifier 不匹配）则不落盘、整批回滚。
- **交互层**：点击引用、弹框打开前（引用身份校验通过后），比较块快照属性与实时数据，不一致则刷新该块的属性和内容（复用现有 `refreshSnapshot`）；刷新失败不阻断弹框打开。
- **UI**：秘密列表多选 + 「移动到…」对话框；提交流程走现有原子管线（clone → crypto → saveData → commit，单写者）。
- **会话撤销**：移动提交成功后，撤销受影响秘密的活动交互会话（关闭任何正打开的相关弹框），沿用 deleteSecret 的 `scope: "secret"` 撤销模式，新增撤销原因。

## 3. Behavior Contract

### 移动

- 勾选同组多条秘密 → 选择目标分组 →（目标组锁定则输入目标组口令；源组锁定则输入源组口令）→ 确认 → 移动成功。
- 移动后秘密出现在目标分组；原分组若为空**不自动删除**（保持现有「需手动删除分组」语义）。
- 秘密 ID 与创建时间不变；`updatedAt` 更新为移动时刻。
- 文档引用（URL、`custom-secret-id`）不变，点击打开仍有效；快照在下次点击时刷新（见下）。

### 引用快照刷新（点击时）

- 打开弹框前：若块快照（label、分组名、时间戳）与实时数据不一致 → 更新该块文本与属性（`custom-secret-label` / `custom-secret-group` / `custom-secret-group-name` 等）。
- 刷新成功后仅用 `showMessage` 提示（如「已刷新引用快照：分组名 API → default」）；块本身不添加任何状态文案或样式标记（用户确认，2026-09）。
- 刷新失败（块被删除/属性已变化等）：弹框照常打开，不因快照刷新失败阻断交互。
- 只处理被显式点击的块；不做文档扫描、不自动改其他引用。

### 错误与边界

- 目标分组不存在 → 拒绝并提示。
- 目标分组 = 当前分组 → 界面不允许（目标列表不含当前组）。
- 源组或目标组口令错误 → 拒绝移动，内存与落盘数据均不变。
- 批量中任一条失败（如某条密文无法解密）→ 整批回滚，无部分提交。
- 移动成功但某分组接口已失效（如上下文已销毁）→ mutation 失败，数据不变。

## 4. Implementation Decisions

- `VaultController` 新增批量移动操作（参数：访问上下文、secret ID 列表、目标分组 ID），内部：
  - 校验目标分组存在；过滤已在目标分组的 secret（无变更项则快速返回）；
  - 对每条秘密按各自源组解密（需已授权，未授权即口令错误语义）；
  - 全部解密成功后才用目标组密钥重加密并一次性持久化（保证整批原子）；
  - 提交成功后 `publishSnapshots()`，并对每个移动的 secret 发出 `scope:"secret"` 撤销（新撤销原因 `secret-moved`）。
- 复用现有加密函数（`encryptSecretContent` / `decryptSecretContent`），不引入新加密原语。
- 弹框交互控制器在 `matchesReference` 之后新增「按需快照刷新」步骤：
  - **比对零额外请求**：复用 `matchesReference` 已取得的块属性（一次 `getBlockAttrs`），与实时 SecretRecord / 分组名做纯内存比较；
  - **异步刷新、不阻塞弹框**：发现陈旧时立即先打开弹框（弹框内容来自实时数据，不依赖块快照），刷新写操作（更新文本与属性 + 写后复核）异步执行；成功仅 `showMessage` 提示，失败不阻断弹框（可附非阻断警告）；
  - 写操作与用户编辑并发时由现有 `matchesReference` 身份校验 + 写后复核兜底，失败按现有 `snapshotWarning` 语义处理。
- UI：
  - 秘密列表新增多选状态（选择条数 + 「移动到…」+ 取消）。
  - 移动对话框：目标分组下拉（排除当前组）、按需口令输入、批量摘要确认。
  - 移动成功后显示成功消息；视图停留在原分组（默认，可调整）。
- 不需要新增 Vault schema 字段；`VaultData` 结构不变。

## 5. Acceptance Criteria

技术验证：
1. `pnpm check`（svelte-check）通过。
2. 构建通过（`pnpm build`）。
3. 数据层检查：目标组锁定且口令错误时移动失败，`vault.json` 与内存状态与操作前逐字节一致（可选单测覆盖：无法解密 → 整批回滚）。

用户验证（desktop，两个分组各设口令）：
1. 勾选 2 条以上秘密移动到已解锁的目标组 → 全部出现在目标组、原组减少；引用点击正常打开。
2. 两组均锁定时（截图场景）：输入源组与目标组口令 → 移动成功；错误口令 → 提示「口令错误」，数据不变。
3. 移动后打开含旧快照引用的文档 → 点击引用 → 块文本与属性更新为新分组名，弹框正常显示；刷新反馈仅 showMessage，块上无状态文案。
4. 用工作台编辑某秘密的 label 后打开其引用 → 点击时该引用文本/属性更新为新 label。
5. 删除一个正被引用的秘密后点击其引用 → 快照刷新失败不阻断弹框（弹出「秘密不存在」等既有行为）。
6. 刷新性能：陈旧块点击时弹框立即出现（不被写操作阻塞）；正常（非陈旧）块点击响应与当前版本无差异。

回归检查：创建/编辑/删除秘密、解锁/改口令、删除分组、迁移中心（v1→v4）行为不变。

## 6. Open Questions

- [默认采用，可调整] 批量移动失败策略：整批原子回滚（推荐），而非「部分成功并报告」。
- [默认采用，可调整] 移动成功后视图停留在原分组并显示成功消息，而非自动跳转到目标分组。
- [默认采用，可调整] 快照刷新失败时静默继续（弹框照常打开），是否给非阻断提示待 UI 评审。
- 移动是否需要在「复制为文档块」等既有动作旁再多一个入口（列表项右键菜单），仅作为多选之外的快捷入口 —— 非阻塞，可 defer。

## 7. Terminology

| 术语 | 含义 |
|---|---|
| 分组（group） | 秘密的容器，每个分组有独立口令与派生密钥；`SecretGroup` |
| 秘密（secret） | 一条加密内容 + label + 时间戳；`SecretRecord`，ID 形如 `sec_xxx`（`makeId("sec")` 生成，UUID） |
| 引用（reference） | 文档中的 v4 段落块：`🔐 [label](siyuan://plugins/.../secret/sec_xxx) · 分组名`，携带 `custom-secret-*` 快照属性；块属性 `custom-secret-id` 为权威身份 |
| 快照（snapshot） | 块属性中存放的展示性副本（label、分组名、时间戳），非权威、可能陈旧，打开时按实时数据刷新 |
| AAD | AES-GCM 附加认证数据：`siyuan-secret-vault:v1:group:<groupId>:secret:<secretId>`，使密文绑定分组与秘密 ID |
| 撤销（revocation） | 授权边界失效通知；`scope:"secret"` 撤销会关闭该秘密正在打开的弹框 |
